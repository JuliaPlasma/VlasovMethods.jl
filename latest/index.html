VlasovMethods.AnalyticHamiltonian — Type
AnalyticHamiltonian(β)

The Hamiltonian of the analytic quadratic-potential model, $H(q, p) = ½|p|² + ½β²|q|²$, for a state x = [q; p] of 2N entries, and the ∇H! of the reduced forms of ReducedBasisMethods. The two halves are the two halves of x.

The instance is both:

  • the gradient, called as ∇H!(g, t, x, params), which writes ∇H(x) — the first block β²q and the second p — into g and returns it. It is what ReducedBasisMethods.reduced_ode and ReducedBasisMethods.reduced_pode take as their ∇H!, and it is not RBM's hamiltonian_gradient!, which is the reduced gradient of a SymplecticDEIM;
  • the Hamiltonian, called as h(t, x, params), which returns H(x).

Neither call reads t or params: the model is autonomous and takes no equation parameters. The gradient accepts any element type, which Newton's JacobianAutodiff needs — the Lobatto IIIA–IIIB(2) run of the PODE form calls the vector field with ForwardDiff.Dual states.

Example

h = AnalyticHamiltonian(6.0)
z₀ = project(b, x₀)
prob = reduced_pode(b, h, (0.0, 1000.0), 1e-4, z₀)

VlasovMethods.CollisionEntropy — Method
(ent::CollisionEntropy)()

The discrete entropy

\[S_h = \int_\Omega f_s \, \log f_s \, dv ,\]

evaluated on the Gauß-Legendre grid the spline basis already carries, in any number of velocity dimensions.

The sign is the manuscripts' `S`

Both manuscripts define $S = -\int f \log f$ in the continuum and then report $\int f_s \log f_s$ in their figures; this returns the latter, so it decreases monotonically. Read as "entropy" with the manuscripts' continuum sign it is $-S$, and a plot of it labelled "entropy" and expected to grow is inverted.

VlasovMethods.ElectricField — Type
ElectricField

The electric field of a one-dimensional Vlasov–Poisson problem on particles.

A field deposits particle positions with their weights, solves for the potential, and evaluates the field $E(x) = -\partial_x \phi(x)$ at particle positions. Its interface is two functions and three call forms:

update!(f, x, w, t)     # deposit the positions `x` with the weights `w` at the time `t`
efield!(f, e, x)        # write `E` at each position of `x` into `e`
f(e, x, w, t)           # `update!` followed by `efield!`
f(e, x)                 # `efield!` alone
f(x, w, t)              # both, into an `e` that call allocates

update! and efield! are called once per time step of a march, so a concrete field holds the buffers it needs and neither function allocates. energy(f) and coefficients(f) read the field energy and the potential coefficients of f. A reduced field, such as ReducedElectricField, holds a full-order field and lifts into it.

update! and efield! are not exported, so a caller reaches them through the three call forms above, as VlasovMethods.update! and VlasovMethods.efield!, or with using VlasovMethods: update!, efield!. Neither is the PoissonSolvers.update! that a PoissonField calls on its own potential: that one solves the potential's linear system, and it is a different function that happens to carry the same name.

VlasovMethods.GridDistribution — Type
GridDistribution{DT, XT, VT, FT}

The distribution function of a 1D1V phase space, stored as its values at the nodes of an nx × nv grid. It is a DistributionFunction{DT, 1, 1}, beside ParticleDistribution and SplineDistribution.

The grid

  • x is periodic: $x_i = x_a + (i-1) h_x$ for $i = 1, \dots, n_x$, with $h_x = (x_b - x_a) / n_x$. The node $x_b$ is the node $x_a$ again and is not stored.
  • v is bounded: $v_j = v_a + (j-1) h_v$ for $j = 1, \dots, n_v$, with $h_v = (v_b - v_a) / (n_v - 1)$. Both ends of the range are nodes.

values is the nx × nv matrix $f_{ij} = f(x_i, v_j)$. Its column-major linear order, x running fastest, is the order the grid stencils such as _apply_∫dv! use, so vec(dist.values) is their state vector.

Evaluation

dist(x, v) interpolates bilinearly between the four surrounding nodes. It is periodic in x and zero outside $[v_a, v_b]$.

Moments

velocity_moments integrates over v by the rectangle rule, $\int f(x_i, v) \, dv \approx \sum_j f_{ij} h_v$. This is the integral of the interpolant plus $\tfrac{h_v}{2} (f_{i1} + f_{i n_v})$, so it is exact up to the values at the two ends of the velocity range and first order in $h_v$ where those do not vanish.

VlasovMethods.IntegratorParameters — Type
IntegratorParameters(dt, nₜ, nₛ, nₕ, nₚ, nparam)

The parameters of a reduced sweep: the timestep dt, the number of time steps nₜ, the number of saved times nₛ — the initial state included — the number of potential degrees of freedom nₕ, the number of particles nₚ and the number of sampled equation parameters nparam. t holds nₛ times, evenly spaced from 0 to dt·nₜ.

The constructor throws an ArgumentError when nₜ < 1, when nₛ < 2, and when nₛ - 1 does not divide nₜ, so that the saves of the march would write past nₛ or drop the final state. The HDF5 constructor applies the same checks to the stored counts.

Every count is Int, so an Int32 count is a MethodError. The element type T of dt is shared by P₀, Ψ, SS and IC in reduced_integrate_vp, so mixed storage types are a MethodError. The timestep scale params.χ is converted to T by the march.

The HDF5 pair is h5save(h5, IP; path = …) and IntegratorParameters(h5, path). h5save writes into the group at path, and creates it when it does not exist.

VlasovMethods.PotentialReducedTensor — Type
PotentialReducedTensor(tensor::GridTensor{DT, 3}, Pi, Pj, Pk)

The lazy size(Pi, 2) × size(Pj, 2) × size(Pk, 2) array that projects the first two indices of the bracket tensor tensor onto the columns of Pi and Pj, and its third index onto the columns of Pk. With R = ReducedTensor(tensor, Pi, Pj),

PotentialReducedTensor[i, j, k] = ∑_K R[i, j, K] * Pk[K, k] .

Pi, Pj and Pk are matrices with one row per grid node. The nodes are counted in the order of the grid's own linear indices, the first direction fastest, as in vec(dist.values) of a GridDistribution. The grid may have any dimension.

The constructor builds ReducedTensor(tensor, Pi, Pj) first, so the checks of that constructor run here as well: Pi and Pj need one row per node, or it throws a DimensionMismatch, their element type has to be DT, or it throws an ArgumentError, and every direction of the grid needs at least 2w + 1 nodes for the tensor's stencil width w, or it throws an ArgumentError. Pk needs one row per node, or the constructor throws a DimensionMismatch, and the element type DT, or it throws an ArgumentError. An index off the array throws a BoundsError.

The tensor's contract is ReducedTensor's and is assumed, not checked: tensor is a bracket's tensor on the grid that bracket was built on, nonzero only where its stencil says so. bracket_tensor builds such a tensor from an Arakawa. A tensor written by hand on another grid than its bracket breaks the contract silently.

getindex allocates nothing, and neither does materialising the array into a preallocated output.

julia> using GeometricBrackets: Arakawa

julia> gt = bracket_tensor(Arakawa(3, 3, 0.5, 0.5));

julia> size(PotentialReducedTensor(gt, ones(9, 2), ones(9, 1), ones(9, 4)))
(2, 1, 4)

VlasovMethods.ReducedElectricField — Type
ReducedElectricField(field, Ψₓ, Ψₚ, Ψₑ, X)
ReducedElectricField(field, Ψ, X)

The reduced electric field of the full-order field: the lift, solve and project path, with no hyper-reduction. The reduced coordinates X are lifted to the particle positions by Ψₓ, the field is deposited from them and solved, evaluated at the positions lifted by Ψₚ, and projected back by Ψₑ:

update!(f, X, w, t)     # deposit  Ψₓ X  and solve
efield!(f, e, X)        # e = Ψₑ E(Ψₚ X)

A DEIMElectricField of a field basis Ψₑ with DEIM row indices p is the same path, lifted by Ψₓ[p, :] and projected by ΨₓᵀΨₑ Ψₑ[p, :]⁻¹, which evaluates the field at the kₑ interpolation points p instead of at every particle.

For an orthonormal basis Ψ, the three-argument form is the full lift and the transpose projection, ReducedElectricField(field, Ψ, X) = ReducedElectricField(field, Ψ, Ψ, Ψ', X). At full basis size, the reduced field equals the projection of the full-order field onto the basis. See ElectricField for the interface, and DEIMElectricField for the hyper-reduced path.

VlasovMethods.ScaledField — Type
ScaledField(field::ElectricField, χ::Real)

The full-order field as the rescaled state of a march sees it: efield! divides the field of field by χ², and energy divides its energy by the same χ². That is not the energy of the divided field, which is quadratic in the field and would carry χ⁴. update! and coefficients forward to field unchanged, because the deposit and the solve carry no amplitude.

It is an ElectricField, so a reduced march wraps it as ReducedElectricField(ScaledField(field, χ), Ψ, X). A march takes its scale from params.χ, so it marches a ScaledField, or a reduced field over one, only when the χ stored here equals params.χ, and throws an ArgumentError that names both values otherwise. It refuses a ScaledField over a ScaledField at any χ (see integrate_vp).

χ must be finite and positive; the constructor throws an ArgumentError otherwise, which refuses 0, a negative and NaN alike. Each division converts χ to the element type of the value it divides, so a Float32 field with a Float64 χ keeps Float32.

VlasovMethods.Snapshots — Type
Snapshots{T, PS}

The snapshots of a parameter sweep: the positions X, the velocities V, the accelerations A, the potentials Φ, and the diagnostics W, K and M, on the sweep's ParameterSpace.

X, V and A are indexed [component, particle, time, sample] and have the size (nd, nₚ, nₛ, nparam), with nparam = length(paramspace). X[:, :, t, p] is the (nd, nₚ) matrix of the positions saved at the t-th of the nₛ saved times of the sample paramspace(p), X[i, j, t, p] is component i of particle j, and V and A hold the velocities and the accelerations of that state the same way. So vec(X[:, :, t, p]) is the component-fastest order of vec(particles.x) of that state, and a snapshot matrix built from these arrays has one column per saved time and sample.

Φ has the size (nh, nₛ, nparam): the potential is a scalar on the one dimension of the Poisson problem, so it carries no component axis, and nh is the number of degrees of freedom of the sweep's Poisson solver. W, K and M have the size (nₛ, nparam), one value each per saved time and sample. W is the field energy, not a particle weight: the snapshots store no weights.

The component count nd of X, V and A and the degree count nh of Φ are the leading extents of those arrays, so they are read from the arrays rather than stored beside them.

== compares all eight fields, paramspace included.

VlasovMethods.SplineDistribution — Type
SplineDistribution(xdim, vdim, nknots, s_order, domain, length_big_cell, bc = Free())

Build a SplineDistribution on nknots equally spaced breakpoints across domain, of spline order s_order, with boundary condition bc on every velocity axis.

s_order is the order $k = p+1$, the same convention as SimpleSplines.order — so s_order = 4 is the cubic basis both collision-operator manuscripts specify, and s_order = 3 is quadratic.

length_big_cell > 0 appends one oversized cell of that width at each end of domain, outside it, giving a GeneralMesh. That is the device for keeping a particle that strays out of the resolved region inside the support of the basis; with 0 the mesh is uniform on domain exactly.

domain is anything with a first and a last — a two-tuple, a vector or a range.

bc may be a SimpleSplines.BoundaryCondition, a two-tuple for the two ends, or one of the symbols :Dirichlet, :Periodic and :nothing that the drivers in scripts/ use, where :nothing means Free(). Any other symbol is an error. The default is Free() — the unconstrained clamped basis, which is the only choice that reproduces $1$, $v$ and $v^2$ and hence the only one on which the conservative schemes conserve.

The mass matrix is always the exact Galerkin one, $\mathbb{M}_{ij} = \int \varphi_i \varphi_j$; there is no lumped-mass option.

VlasovMethods.SplineDistribution — Type
SplineDistribution{DT, XD, VD}

The distribution function represented as a spline in velocity, $f_s(v) = \sum_I \hat{f}_I \, \varphi_I(v)$, together with everything needed to project onto it and to integrate against it.

VD is the number of velocity dimensions. For VD == 1 the basis is a one-dimensional SimpleSplines B-spline basis and the coefficients are a vector; for VD > 1 it is a TensorProductBasis and the coefficients are a VD-dimensional array. Nothing else about the two cases differs — the evaluation, the projection and the mass solve are the same calls.

Fields

  • spline — the SimpleSplines.Spline, which shares coefficients. A projection writes that array, and every reference to the spline sees the new function without a rebuild.
  • basis — the spline basis.
  • quadrature — the assembly table: the basis tabulated at the Gauß-Legendre points, the weights, and the mass operator.
  • coefficients — the degrees of freedom $\hat{f}$.

The mass matrix is never formed as a Kronecker product

For VD > 1 the mass matrix is $\mathbb{M}^{(VD)} \otimes \dots \otimes \mathbb{M}^{(1)}$, and a solve is VD one-dimensional solves applied along each axis. That is an identity, not an approximation, and it is what makes the higher-dimensional cases tractable at all: forming the product and factorising it densely would mean a 1681×1681 matrix for the 41-element cubic basis of a two-dimensional velocity space, and 68921² in three dimensions, which does not fit.

The boundary condition is not a free choice

The $L^2$ projection reproduces $\int \pi(v) f \, dv$ for a polynomial $\pi$ exactly when $\pi$ lies in the span of the basis, so the mass, momentum and energy of $f_s$ agree with those of the particles only if $1$, $v$ and $v^2$ are in the span. polynomial_reproduction(basis) reports the largest degree available: p for the clamped basis (Free()), 0 for a periodic one — $v$ is not periodic — and -1 for a Dirichlet-recombined one, where not even the constants survive.

Measured on a cubic basis over $[-8,8]$ by scripts/verify_conservation.jl: Free() reproduces all three to $10^{-14}$, Periodic() gets $v$ wrong by $1.2$ and $v^2$ by $0.12$, and Dirichlet() gets even the constant wrong by $4 \times 10^{-2}$.

What this does and does not break

It does not by itself break the particle-level conservation of the conservative Lenard-Bernstein operator: its coefficients $A_1, A_2$ are solved from the two conservation constraints, which are conditions on particle sums, so $\sum_\alpha w_\alpha \dot{v}_\alpha$ and $\sum_\alpha w_\alpha v_\alpha \dot{v}_\alpha$ vanish at round-off on any basis. What it breaks is the agreement between the particle and spline representations, and therefore every diagnostic computed from $f_s$ — the entropy above all, which is what the H-theorem is a statement about. See check_conservation_basis.

VlasovMethods.VlasovHamiltonian — Type
VlasovHamiltonian(model)

The energy of the Vlasov–Poisson model model, as an invariant h(t, q, params),

\[h(t, q, w) = \frac{1}{2}\sum_i w_i v_i^2 + \frac{1}{2}\int (\partial_x\phi)^2 \,\mathrm{d}x ,\]

where $\phi$ solves the Poisson problem for a fresh deposit of the positions in q with the weights params.w. The call leaves that deposit in model.potential. Each acceleration substep deposits its own state before it reads the field, so this does not change a trajectory.

The field term is the Gauss quadrature of $(\partial_x\phi)^2$ on the basis of the potential, tabulated once by the constructor, so a call allocates nothing. Its terms are non-negative, so the sum keeps their relative accuracy also for a small field.

VlasovMethods.VlasovPoisson — Type
VlasovPoisson(dist::DistributionFunction, potential::Potential)

The Vlasov–Poisson model of one species with the distribution dist, whose field is the solution of potential.

For a ParticleDistribution or a SplineDistribution, the field is the potential's solve for the deposit of the distribution, and potential is on a B-spline basis.

For a 1D1V GridDistribution, the field is $\phi = G \rho$ with $\rho_i = h_v \sum_j f_{ij}$, and the constructor assembles the $n_x \times n_x$ Green's matrix $G$ of the potential's backend once. GeometricIntegrator(model, tspan, tstep, method) steps the model. The constructor throws:

  • ArgumentError unless the potential's solver is a PoissonSolverFFT or a PoissonSolverMatrixFree;
  • DimensionMismatch unless the potential has one degree of freedom per x-node of dist;
  • ArgumentError unless the potential's x-nodes are dist.x, and unless dist has at least three nodes in each direction.

The grid scheme is periodic in v: it is valid only while f vanishes to eps(T)·maximum(f) at both ends of the velocity range.

VlasovMethods.VlasovWithExternalFields — Type
VlasovWithExternalFields(dist, field; charge = one(T), mass = one(T))

A VlasovModel of one particle species in an external electromagnetic field: the particles of dist, a ParticleDistribution{T,3,3}, pushed by field. charge and mass are the species' charge and mass, in units in which the equation of motion reads ẍ = (q/m)(E + ẋ × B), and both are stored as T. The constructor throws an ArgumentError unless the converted mass is positive. An empty particle list is a vacuum run and not an error: the model, its SplittingMethod and run! work over the empty state.

The field is any value that defines electric_field and magnetic_field for an SVector{3} coordinate; the model puts no bound on the type of its field parameter, so the two functions are the whole contract. UniformField is the field type this package ships, and the ElectromagneticFields extension adds the two methods for that package's FieldFunctions of a Cartesian chart — FieldFunctions(ABCEquilibrium(a, b, c)) is passed to the constructor as it is. In a curvilinear chart the components are not Cartesian, so the extension defines no method and the first kick raises its MethodError.

The method is SplittingMethod(model, tspan, tstep): a Strang splitting of the drift ẋ = v and the Lorentz force v̇ = (q/m)(E + v × B), with the rotational part of the force a Boris push. One step is a half drift, two half Boris pushes with the field evaluated at the step's start, and a half drift. GeometricIntegrators.integrate(method.integrator) and run!(method, h5file) serve it as they serve the Vlasov–Poisson model.

VlasovMethods.CLB_rhs_GI! — Method

The conservative Lenard-Bernstein right-hand side,

\[\dot{v}_\alpha = - \nu \left( \frac{f_s'(v_\alpha)}{f_s(v_\alpha)} + A_1 + A_2 v_\alpha \right) ,\]

which is eq:velocity_ode of the Lenard-Bernstein manuscript with the opposite sign.

The sign here is the correct one and the manuscript's is not

The manuscript writes $\partial_t f = \partial_v (a f)$ with $a = \nu (f'/f + A_1 + A_2 v)$ and then $\dot{v}_\alpha = a(v_\alpha)$. Continuity is $\partial_t f + \partial_v (U f) = 0$, so $\partial_t f = +\partial_v(a f)$ forces $U = -a$ and hence $\dot{v} = -a$. The check: for a Maxwellian of width $\sigma > 1$ — too broad — $a = \nu v (1 - \sigma^{-2}) > 0$ for $v > 0$, so $\dot v = +a$ would push particles outward and widen an already too-wide distribution instead of relaxing it. Conservation is unaffected either way, the constraints being homogeneous, so no published result changes; but the ODE as typeset relaxes backwards in time.

VlasovMethods.compute_J! — Method
compute_J!(J, g, values, sdist, ::MetriplecticLenardBernstein)

The vector $\mathbb{L}_k = \sum_i \mathbb{M}^{-1}_{ik} \int \varphi_i \, (1 + \log f_s) \, dv$ of the Landau manuscript's eq:defn_Lk, which is exactly the $L^2$ projection of $1 + \log f_s$ onto the basis.

This discretisation projects $1 + \log f_s$ onto the spline space and differentiates the projection, where eq:velocity_ode of the Lenard-Bernstein manuscript uses the pointwise ratio $f_s'(v_\alpha)/f_s(v_\alpha)$. The two agree only up to the projection error of the logarithm. That is deliberate and is what makes this a genuine discrete-gradient system: J is $\partial S_h / \partial f_i$ for $S_h = \int f_s \log f_s \, dv$.

The logarithm is unguarded in the manuscripts and guarded here

The earlier implementation wrote 0.5 * log(f_s^2). That is log|f_s| exactly, and its derivative is f_s'/f_s for either sign, so the drift it produces is finite and plausible-looking wherever f_s < 0. What it is not is the entropy: S = ∫ f log f requires f > 0, and where f_s < 0 the H-theorem reverses — dS/dt = -ν ∫ F²/f dv becomes positive. So the construction converted a positivity violation from a visible DomainError into an invisible wrong answer, and removed the only diagnostic that would have caught it. Positivity is checked here instead.

VlasovMethods.compute_L! — Method
compute_L!(L, sdist, landau; chunk = 256)

The symmetric matrix

\[\mathbb{L}_{ij} = \frac{1}{2} \int_\Omega \! \int_\Omega \big( \nabla \varphi_i(v) - \nabla \varphi_i(v') \big) \cdot f_s(v) \, U(v,v') \, f_s(v') \cdot \big( \nabla \varphi_j(v) - \nabla \varphi_j(v') \big) \, dv \, dv'\]

of the Landau manuscript's eq:discrete-landau-matrix.

Method

Expanding the two differences gives four terms. With $U$ symmetric in its arguments and in its indices, relabelling $v \leftrightarrow v'$ shows the first and fourth are equal and the second and third are equal, so the factor of one half cancels and

\[\mathbb{L} = \sum_{c,d} D^c \operatorname{diag}(s \odot A^{cd}) (D^d)^{\mathsf T} - \sum_{c,d} \big( D^c \operatorname{diag}(s) \big) \, U^{cd} \, \big( D^d \operatorname{diag}(s) \big)^{\mathsf T} , \qquad A^{cd}_a = \sum_b s_b \, U^{cd}_{ab} ,\]

with $s_a = w_a f_s(v_a)$ and $D^c$ the sparse gradient tables above. This is an identity, not an approximation: the same quadrature sum, rearranged.

Both terms are sparse-times-dense products. The first is a single pass over the grid; the second is the genuinely coupled one, and its $Q \times Q$ kernel is built and consumed in row blocks of chunk so that nothing of that size is ever held.

$U^{cd}$ is symmetric in $(c,d)$, so each block is swept once and its three independent components serve all four contractions. The whole assembly therefore costs $O(Q^2)$ kernel evaluations, two sweeps of the grid pairs in total: one for $A^{cd}$ and one for the blocks.

VlasovMethods.growth_rate — Method
growth_rate(t, W; window = 2, maxima = 2:5)

The growth rate $γ$ of the field energy history W at the times t: half the least-squares slope of $\log W$ over the selected local maxima, because $W ∝ |E|² ∝ e^{2γt}$. The times are physical time, so this is the physical growth rate.

A maximum is a point no lower than the window points on each side, whose first differing sample on its right is lower. A flat maximum counts once, at its first index, and a rising shoulder, a plateau that ends in a higher sample, is no maximum. maxima selects which of them the fit uses, by their order along t, which drops the first few maxima; the fit runs in eltype(W), so it takes no dependency on Statistics.

VlasovMethods.integrate_vp — Method
integrate_vp(P₀, params, efield, SS, IP, p; save = true)

The full-order leapfrog march of an ElectricField, the same march as reduced_integrate_vp without a basis: the state of P₀ advanced IP.nₜ steps of IP.dt by full_leapfrog_step!, with one kick of the full field of efield per step. A reduced model marches the ScaledField of the same field, so the two marches of one comparison take the same field and the same χ, which is params.χ. With nsave = nₜ/(nₛ - 1), the state of every nsave-th step it, the initial state included, is written into the save div(it, nsave) + 1 of the sample p of the snapshots SS by save_full_solution.

The march holds its own buffers, so efield is the only state it shares with the caller: P₀ is copied and never written, and the march needs no cache argument.

params is the caller's, and it must hold χ. The χ scale is a timestep scale and nothing else: the step is Δt = IP.dt·T(params.χ), converted to the march's element type before the product, and the times handed to the field are unscaled: the kick of step it is at its midpoint (it - ½)·IP.dt, and the save of step it at it·IP.dt. So a time-independent field marched with (dt, χ = 2) equals the same field marched with (2dt, χ = 1) state for state.

params.χ is the one source of the scale. When efield is a ScaledField, or a ReducedElectricField over one, the χ the ScaledField was built with must equal params.χ, and the field and its energy are divided by the χ² of the step. Any other field is marched as it is.

It returns nothing; the states are in SS, and the integration parameters hold the times.

Throws

  • ArgumentError when the snapshots carry another number of components than one; when params.χ is not finite and > 0, which refuses 0, a negative, Inf and NaN alike, as ScaledField does; when efield is a ScaledField, or a ReducedElectricField over one, built with another χ than params.χ, naming both; and when that ScaledField is over a ScaledField, at any χ. The counts of IP are checked by IntegratorParameters itself.
  • DimensionMismatch when the snapshots do not hold IP.nₛ saved times, and when the particle list holds another number of particles than the snapshots do.
  • The NamedTuple's own error when params holds no χ. There is no default.

Cost

The loop's two calls — full_leapfrog_step! and save_full_solution — are inferred and allocate nothing. The buffers of the state are allocated once, before the loop.

VlasovMethods.kernel — Method
kernel(v_α, v_β, ::Landau)

The Landau collision kernel

\[U(u) = \frac{1}{|u|} \left( \mathbb{I} - \frac{u \otimes u}{|u|^2} \right) , \qquad u = v_\alpha - v_\beta ,\]

the orthogonal projector onto the complement of $u$, scaled by $1/|u|$.

This is the standard Landau tensor and it is not what the manuscript's eq:landau_kernel as typeset says: that carries a prefactor $1/|u|^3$ in front of the bracketed projector, i.e. an extra $|u|^{-2}$. The intended reading is $|u|^{-3} ( |u|^2 \mathbb{I} - u \otimes u )$, which is this. The properties the conservation proofs rest on hold for the expression implemented here: $U$ is symmetric, $U(v_\alpha, v_\beta) = U(v_\beta, v_\alpha)$, and $U u = 0$ exactly.

The coincident-point value is a regularisation, not a limit

$U$ diverges as $|u| \to 0$; there is no value to return there. Zero is returned so that a product quadrature whose two factors share nodes does not produce Inf, but the error this introduces does not vanish under refinement — and because both factors of the double integral in compute_L! use the same Gauß-Legendre nodes, it fires on every diagonal cell pair rather than on a set of measure zero. The kernel is integrable in two dimensions, so the integral itself is finite; what is needed is a quadrature that knows about the singularity, or offset grids for the two factors. Neither is implemented.

Deposit the particle weights of distribution onto the basis of potential, writing the charge density into the potential's right-hand side buffer.

VlasovMethods.projection — Method
projection(velocities, dist::ParticleDistribution, final_dist::SplineDistribution)

Project the particles onto the basis of final_dist, writing the coefficients into it and returning its Spline.

velocities is a vector for a one-dimensional velocity space and a VD × N matrix otherwise; it is passed separately from dist because the implicit solvers evaluate the right-hand side at a stage value rather than at the particles' stored positions.

A particle outside the domain is an error, not a warning

The velocity domain is truncated and the true one is not, so a particle can leave. When it does there is nothing sensible to do with it: it contributes nothing to the projection, so its weight is lost from $f_s$ while it keeps moving, and f_s then evaluates to zero at its position — which makes the $f_s'/f_s$ of every collision operator here a division by zero. The Lenard-Bernstein manuscript says as much in its closing remarks.

A DomainError naming the count and the domain is therefore the only useful response: a run that has lost mass is not a run whose output means anything. Enlarge the domain, or give the mesh oversized end cells with length_big_cell.

VlasovMethods.rhs_downstairs_factor! — Method

The metriplectic Lenard-Bernstein right-hand side, $\dot{v} = \mathbb{L} \, \partial S_h / \partial v$ with the bracket

\[\mathbb{L}_{\alpha\beta} = - \frac{n_h}{w_\alpha} \, \delta_{\alpha\beta} + \frac{(\varepsilon_h - u_h v_\alpha) + (v_\alpha - u_h) v_\beta}{\varepsilon_h - u_h^2} .\]

$\mathbb{L}$ is symmetric and satisfies $\sum_\alpha w_\alpha \mathbb{L}_{\alpha\beta} = 0$ and $\sum_\alpha w_\alpha v_\alpha \mathbb{L}_{\alpha\beta} = 0$, so momentum and energy are exact Casimirs of the bracket whatever dS is — a stronger structure than the manuscript's, and the reason these runs conserve.

The weight is per particle, read from pdist for each $\alpha$: the two degeneracies above are what fail if a single weight is used for every particle, so with non-uniform weights the conservation the bracket is built for would be lost.
